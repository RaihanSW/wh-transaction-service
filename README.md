- generate docs : make docs or swag init

## Setup Database (Migration & Seeding)

Service memakai 1 database Postgres: `warehouse_db` untuk semua
operasi (read & write, tanpa replica).
Migrasi/seeding dijalankan lewat subcommand di `main.go` — tidak perlu
eksekusi SQL manual ke DB.

### 1. Siapkan config

```bash
cp template_application_local.json application_local.json
```

Isi di `application_local.json`:

- `database.warehouse_db` →
  `username`, `password`, `hostname` (`host:port`), `dbname`
- `secretkey` → base64 string

`ReadConfig` membaca file `application_<env>.json` sesuai flag `-env`
(mis. `-env local` → `application_local.json`). `InitDBConnection`
membuka koneksi `pgx` ke tiap key di map `database` dengan DSN
`postgres://<username>:<password>@<hostname>/<dbname>`.

### 2. Jalankan migration

```bash
# lihat status migrasi (applied/pending)
go run main.go -env local migrate status

# apply semua migrasi yang pending
go run main.go -env local migrate up

# rollback — default 1 step, atau n step
go run main.go -env local migrate down
go run main.go -env local migrate down 2
```

Yang dibuat migrasi saat ini (folder `migration/`):

| Version | Name | Isi |
|---|---|---|
| 202611110001 | `create_transaction_schema_tables` | schema `"Transaction"` + 5 tabel (lihat daftar di bawah) |
| 202611110002 | `lookup_id_to_identity` | kolom `id` 3 tabel lookup → `GENERATED BY DEFAULT AS IDENTITY` |

Semua tabel yang dicakup migrasi project ini:

| Tabel | Keterangan |
|---|---|
| `"Transaction".transaction` | transaksi utama — `uid` VARCHAR(16) PK (DB-generated), `code`, `dateprocess`, `ttl_weight`, `status` → `transaction_status`, `end_date`, `ttl_volume` + audit cols |
| `"Transaction".transaction_status` | lookup status transaksi — `id` INT PK identity, `name` VARCHAR(32) |
| `"Transaction".goods` | barang per transaksi — `uid` VARCHAR(16) PK (DB-generated), `dateprocess`, `transaction_uid` → `transaction`, `category_id` → `goods_category`, `status` → `goods_status`, `expired_date` |
| `"Transaction".goods_category` | lookup kategori barang — `id` INT PK identity, `name` VARCHAR(32) |
| `"Transaction".goods_status` | lookup status barang — `id` INT PK identity, `name` VARCHAR(32) |
| `transaction_schema_migration` | tracking migrasi (auto-create, bukan bagian schema `"Transaction"`) |

Audit cols di semua tabel: `created_at`, `created_by` VARCHAR(64),
`updated_at`, `updated_by` VARCHAR(64).

Tiap migrasi tercatat di tabel `transaction_schema_migration`
(auto-create) di DB target — terpisah dari `schema_migrations` milik
service User. `migrate up` aman dijalankan berulang — yang sudah
applied di-skip. Target DB ditentukan field `DBKey` di tiap file
migrasi (selalu writer, bukan replica).

Menambah tabel/kolom baru = buat file `migration/<version>_<name>.go`,
register `Migration{Version, Name, DBKey, Up, Down}` via `init()`.
Pakai timestamp-style version, mis. `202611100001`.

### 3. Jalankan seeding

```bash
# semua seeder
go run main.go -env local seed

# satu seeder tertentu
go run main.go -env local seed transaction_status
go run main.go -env local seed goods_category
go run main.go -env local seed goods_status
```

Seeder yang tersedia (folder `seed/`, idempotent — aman diulang):

| Name | Isi |
|---|---|
| `transaction_status` | `Draft`(1), `Process`(2), `Done`(3) → `"Transaction".transaction_status` |
| `goods_category` | `General`(1), `Perishable`(2), `Fragile`(3) → `"Transaction".goods_category` |
| `goods_status` | `Available`(1), `Reserved`(2), `Expired`(3) → `"Transaction".goods_status` |

Catatan: nilai lookup masih placeholder — sesuaikan di tiap file
`seed/*_seeder.go`. Seeder juga menyelaraskan identity sequence
(`setval`) setelah insert id eksplisit, agar create lewat API tidak
bentrok PK.

### 4. Start service

```bash
go run main.go -env local
```

Shortcut Makefile: `make migrate-up`, `make migrate-down STEPS=n`,
`make migrate-status`, `make seed NAME=transaction_status` (`ENV=local` default).

## Testing

Unit test memakai stub hand-written (tanpa DB/redis/network), contoh:
`app/service/transaction_service_test.go` dan `app/service/goods_service_test.go`.

```bash
# semua test di package service
go test ./app/service/

# verbose — tampilkan tiap test & subtest
go test ./app/service/ -v

# semua test di project
go test ./...

# hanya test tertentu (regex)
go test ./app/service/ -run TestTransaction -v

# hanya satu subtest
go test ./app/service/ -run 'TestTransactionDelete/sukses' -v

# coverage
go test ./app/service/ -coverprofile=cover.out && go tool cover -func=cover.out
```
