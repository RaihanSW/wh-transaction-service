# dc-transaction-service — Agent Instructions

Go (chi) service template. Boilerplate ticket CRUD on schema `transaction_ticket` + warehouse tables on schema `"Transaction"`.

## Build & Run

```bash
go mod tidy && swag init
go run main.go -env local
```

Config: `application_<env>.json` (`secretkey`, `database`, `redis`, `state`, `jwt`, `log`).

## DB Migration & Seeding

Custom runner, no external deps. Subcommands after flags (default = serve):

```bash
go run main.go -env local migrate up        # apply pending migrations
go run main.go -env local migrate down [n]  # rollback last n (default 1)
go run main.go -env local migrate status    # applied/pending per migration
go run main.go -env local seed [name]       # all seeders, or one by name
```

- `migration/` — registry of `Migration{Version, Name, DBKey, Up, Down}`; `Version` is a `string` (timestamp-style, e.g. `"202611110001"` — sorts lexicographically) stored as `VARCHAR(32)` in `transaction_schema_migration` (auto-created per DB, separate from User's `schema_migrations`). Each file registers via `init()` and declares its target `DBKey` from `cfg.Database` (writer, never replica). New migration = new file `migration/<version>_<name>.go`.
- `seed/` — registry of `Seeder{Name, DBKey, Run}`; seeders must be idempotent (`ON CONFLICT DO NOTHING`).
- Makefile shortcuts: `make migrate-up migrate-down migrate-status seed` (`ENV=`, `STEPS=`, `NAME=`).

## Routes (`app/controller/controller.go`)

- `/ping`, `/health/check`, `/health/check-db`; `/swagger` non-prod
- Transaction slice (`transaction_handler.go` / `transaction_service.go` / `transaction_repository.go` + `query/transaction_queries.go`) on `"Transaction".transaction`, under `/transaction`:
  - `POST /transaction` — `TransactionCreate` (uid DB-generated via `RETURNING`; `TransactionRequest`)
  - `GET /transaction` — `TransactionGetAll`; `GET /transaction/{uid}` — `TransactionGetByID` (reads replica)
  - `PUT /transaction/{uid}` — `TransactionUpdate`; `DELETE /transaction/{uid}` — `TransactionDelete`
- Lookup slice `transaction_status` (`transaction_status_*`) on `"Transaction".transaction_status`, under `/transaction/status`:
  - `POST /transaction/status` — create `{name}` → `RETURNING id` (identity); `GET /` list; `GET|PUT|DELETE /{id}`
- Goods slice (`goods_*`) on `"Transaction".goods`, under `/goods`:
  - `POST /goods` — `GoodsCreate` (uid DB-generated; `GoodsRequest`: `dateprocess`, `transaction_uid`, `category_id`, `status`, `expired_date`)
  - `GET /goods` — `GoodsGetAll`; `GET /goods/{uid}` — `GoodsGetByID`
  - `PUT /goods/{uid}` — `GoodsUpdate`; `DELETE /goods/{uid}` — `GoodsDelete`
- Lookup slices `goods_status` & `goods_category` (`goods_status_*`, `goods_category_*`), under `/goods/status` & `/goods/category` — same shape as `/transaction/status`

chi static segments (`status`, `category`) win over `{uid}` — no route conflicts. All slices: create → 201, get/update/delete → 200, not found → 404; audit cols `created_by`/`updated_by` filled with `service_name` by repo.

The `transaction/` prefix seen in engine configs comes from the service base URL path.

## Databases & Clients

- Single Postgres DB `warehouse_db` — no replica (writer key reused for reads). Schema `"Transaction"` holds `transaction`, `transaction_status`, `goods`, `goods_category`, `goods_status`. Lookup `id` columns are `GENERATED BY DEFAULT AS IDENTITY` (migration `0002`) — seeders may still insert explicit ids.
- Repositories keep the writer+replica signature (`db` + `dbReplica`); `main.go` passes `warehouse_db` for both.
- Redis (`config/redis.go` — connection pool helper, not yet wired in `main.go`)

## Schema `"Transaction"`

```sql
CREATE TABLE "Transaction".transaction_status (
    id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(32) NOT NULL, -- +audit cols
);
CREATE TABLE "Transaction".goods_category (
    id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(32) NOT NULL, -- +audit cols
);
CREATE TABLE "Transaction".goods_status (
    id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(32) NOT NULL, -- +audit cols
);
CREATE TABLE "Transaction".transaction (
    uid         VARCHAR(16) PRIMARY KEY
               DEFAULT upper(substr(md5(random()::text), 1, 16)),  -- DB-generated uid
    code        VARCHAR(16) NOT NULL,
    dateprocess TIMESTAMP,
    ttl_weight  INT,
    status      INT NOT NULL REFERENCES "Transaction".transaction_status (id),
    end_date    TIMESTAMP,
    ttl_volume  INT,
    -- +audit cols
);
CREATE TABLE "Transaction".goods (
    uid             VARCHAR(16) PRIMARY KEY
                   DEFAULT upper(substr(md5(random()::text), 1, 16)),
    dateprocess     TIMESTAMP,
    transaction_uid VARCHAR(16) NOT NULL REFERENCES "Transaction".transaction (uid),
    category_id     INT NOT NULL REFERENCES "Transaction".goods_category (id),
    status          INT NOT NULL REFERENCES "Transaction".goods_status (id),
    expired_date    TIMESTAMP,
    -- +audit cols
);
```

Audit columns on every table: `created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP`, `created_by VARCHAR(64)`, `updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP`, `updated_by VARCHAR(64)`.

- Seeded lookups (placeholder values, adjust in `seed/`): `transaction_status` (Draft/Process/Done), `goods_category` (General/Perishable/Fragile), `goods_status` (Available/Reserved/Expired).
